# AGENTS.md

MemDiff is a provenance- and belief-revision-aware agent memory engine evaluated across two matched-budget benchmark tracks, paired with a static React "Memory Time Machine" replay viewer.

## Architecture & Invariants

- **Bounded contexts, clean layers**: `src/memdiff/{memory,llm,audit,benchmarks/{common,drift_sim,lmev2}}` each hold `domain/` (pydantic models and pure rules) and `application/` (services plus `ports.py` Protocols). Implementations of the ports (SQLAlchemy, OpenAI SDK, HTTP, files, numpy index, offline fakes) live in `adapters/`, argparse CLIs in `presentation/cli/`, and wiring in `bootstrap/`. `.importlinter` enforces the dependency direction across the whole package: `presentation → bootstrap → adapters → benchmarks → audit → memory → llm`, plus `domain` ← `application` inside each context. `benchmarks → audit.application` is intended: `MemoryWorkspace` carries the `ReplayService` that runners need. `domain/` and `application/` never import `sqlalchemy`, `openai`, `httpx`, or `dishka`. Add new top-level packages to the `layers-package` contract (it is `exhaustive`).
- **DI (dishka 1.10)**: `bootstrap/` is the only composition root (`build_container(settings, *overrides)`) and the only place that constructs adapters for presentation, including the replay writer (`DemoProvider`, `DriftSimProvider`, `LMEV2Provider` take per-run paths). Dependencies arrive through constructors, and every value arrives explicitly: no `X or Default()`, no client built inside domain, application, or adapter code; domain config defaults come from pydantic field defaults or `default_factory`. A presentation `main()` calls `get_settings()` once and hands `Settings` to a `run(...)` function that tests call directly. Presentation gets ports (`ReplayWriter`, runners) from the container and supplies UI-only implementations (`TqdmProgress` for the `Progress` port of the LME-V2 runner). Runners get a `MemoryWorkspaceFactory` (`benchmarks/common/application/workspace.py`), never the container. Tests and the offline demo swap adapters with an override `Provider` (`OfflineProvider`, or `FakeSDKProvider` + `fake_settings` from `tests/fake_sdk.py`, which replace the `OpenAI` client), so `tests/` stay offline and deterministic.
- **Matched-budget ablation ladder**: All 4 policies (`naive_rag`, `recency_rag`, `structured_extract`, `belief_revision`) implement `MemoryPolicy` (`memory/application/policy.py`) under the same `top_k` retrieval budget. `memory/application/policies/` depends only on the ports in `memory/application/ports.py` (`Embedder`, `BeliefExtractor`, `BeliefReconciler`, repositories, `UnitOfWork`); the LLM implementations are in `adapters/llm/belief_ops.py`.
- **Immutable belief ledger & time-travel**: Never hard-delete beliefs on revision. Mark old rows `superseded`, `refuted`, or `forgotten`, record directed `BeliefEdge` links, and append `TimelineEvent` entries so `reconstruct_state_at_step()` (`audit/domain/time_travel.py`, served by `ReplayService.state_at_step`) and `computeBeliefAtStep()` (`web/src/App.tsx`) reconstruct identical snapshots. `RevisionAuditRecorder` writes events and edges in the same transaction as the belief change (`SqlUnitOfWork`).
- **ORM**: SQLAlchemy 2.x typed `Mapped[...]` models in `adapters/persistence/sqlalchemy/`, with two separate databases: the per-run ledger (`LedgerBase`) and the LLM response cache (`CacheBase`). Domain models stay free of ORM types; the repositories convert rows.
- **Vector index cache invalidation**: `NumpyVectorIndex` (`adapters/vector/numpy_index.py`) caches normalized `(N, D)` float32 matrices and the repositories fetch full rows in a second `WHERE id IN (...)` query. The REQUEST-scope provider builds one index per repository (`make_belief_index`, `make_chunk_index`) and injects it. Any write to chunk or belief rows must invalidate the matching index: the repositories invalidate on every write, and `SqlUnitOfWork` again on commit, rollback, and close (a rollback undoes cached writes). Equal-score ties follow the autoincrement `seq` column (insertion order), so ordering needs no raw SQL.
- **Prompts**: every prompt lives as a `.md` file under repo-root `prompts/` and is a `string.Template` (`$name`). `PromptCatalog` loads and validates all of them when the container is built, and a missing file or a missing or unknown placeholder aborts startup. Python only formats per-line data (neighbor lines, memory joins). New prompt: add a `PromptId` in `llm/domain/prompt.py`, add the `.md` file, render through the catalog. Prompt text never goes into `.py` files.
- **Schema parity**: Keep `ReplayBundle` and its nested types in `src/memdiff/audit/domain/replay.py` (plus `Belief`, `BeliefEdge`, `TimelineEvent`, `MemoryStats` it embeds) 1:1 synchronized with `web/src/types/replay.ts`.
- **Golden snapshots**: `tests/golden/` pins request bytes, predictions, summaries, and replay JSON from the pre-refactor run. Behavior-preserving changes keep them green. Regenerate with `MEMDIFF_UPDATE_GOLDEN=1` only for a deliberate behavior change, and say so in the commit.

## Two-Track Benchmark Scope

- **Track 1 — LongMemEval-V2 (`src/memdiff/benchmarks/lmev2/`)**: Real ServiceNow (`enterprise`: 100 trajectories, 211 questions) and WebArena (`web`) logs. Here `dynamic-environment` tests interactive UI transitions (`pre-state + action -> post-state`), *not* cross-session temporal overrides. MemDiff targets failure→success `gotcha` revision, surface-scoped `closed_set_items` consolidation (for `*-abs` flawed-premise questions), and ephemeral task-noise filtering.
  - Keep scoring (`domain/scoring/`, `application/scorer.py`) and the `prompts/benchmarks/lmev2/` files faithful to upstream `xiaowu0162/LongMemEval-V2`. On `*-abs` questions, bare `\boxed{UNKNOWN}` scores `0`; the response must identify why the premise is flawed.
  - Fetch data via `uv run python scripts/fetch_lmev2_small.py --domain enterprise --include-question-screenshots` (streams `trajectories.jsonl` down to ~94 MB + 2.6 MB question screenshots and skips the 5.6 GB trajectory screenshot archive).
- **Track 2 — DriftSim (`src/memdiff/benchmarks/drift_sim/`)**: Deterministic state-machine stress test owning 100% of ground truth for temporal fact contradictions (`Stale Belief Rate`) and early-session `Durable Rule Preservation`. `DriftSession.to_trajectory_dict()` adapts sessions to the exact trajectory dict shape used by Track 1. DriftSim imports nothing from `lmev2`; shared answer helpers live in `benchmarks/common/domain/answer.py`.

## Local Ollama & `qwen3.5:9b` Runtime Conventions

- Run `uv run python scripts/check_ollama.py` before live evaluations. Configure endpoints and models in `.env` (see `.env.example`); `bootstrap/settings.py` defines every setting.
- Launch Ollama with `OLLAMA_CONTEXT_LENGTH=32768` on 12 GB VRAM hosts (`qwen3.5:9b` + `qwen3-embedding:0.6b` fit co-resident on GPU at 32K; default 4K truncates RAG/thinking prompts, while 128K spills to CPU).
- `qwen3.5:9b` thinks by default: keep `max_tokens=16384` in every `ChatRequest` the adapters build (Reader, Extractor, Reconciler, Judge) and `llm_timeout_seconds=600`, so thinking never exhausts the token cap before emitting `content`.
- To disable thinking over Ollama's `/v1/chat/completions`, set `think=False` on the `ChatRequest`; `OpenAIChatModel` (`adapters/llm/openai_compat.py`) sends `extra_body={"reasoning_effort": "none"}` (Ollama's `/v1` endpoint ignores `"think": false`) and uses `max_tokens` instead of `max_completion_tokens` whenever a base URL is set.
- `CachingChatModel` / `CachingEmbeddingModel` (`llm/application/caching.py`) persist responses through `SqlLLMResponseCache` in `.cache/llm/llm_cache.db` and skip caching empty `""` chat outputs. When resuming interrupted `DriftSim` runs, pass `--resume` to `scripts/run_drift_sim.py` to reuse the existing SQLite ledgers (`DriftRunStore`). Re-running `belief_revision` from scratch generates new random `b_*` IDs that miss reconciler cache entries.

## Context Pointers

- `manual/` is a scratch board of human-facing explanations (code map, DB schema, run guide). It may be outdated, so don't treat it as a source of truth: verify against the code. Don't update it unless the user asks.
- Modifying belief lifecycle, SQLite storage, or time-travel replay → read `src/memdiff/memory/domain/belief.py`, `src/memdiff/audit/domain/time_travel.py`, `src/memdiff/adapters/persistence/sqlalchemy/ledger.py`, `tests/test_memory_audit_core.py`, and `tests/test_sql_ledger.py`.
- Tuning extraction/reconciliation prompts or adding a policy → read `prompts/memory/`, `src/memdiff/adapters/llm/belief_ops.py`, `src/memdiff/memory/application/policies/belief_revision.py`, and `tests/test_prompt_catalog.py`.
- Changing LongMemEval-V2 scoring, prompting, or dataset loading → read `src/memdiff/benchmarks/lmev2/domain/scoring/`, `src/memdiff/benchmarks/lmev2/application/{scorer,runner}.py`, `src/memdiff/adapters/llm/{judges,lmev2_reader}.py`, and `prompts/benchmarks/lmev2/`.
- Changing LLM transport, caching, or providers → read `src/memdiff/llm/application/`, `src/memdiff/adapters/llm/openai_compat.py`, `src/memdiff/bootstrap/providers.py`, and `tests/test_llm_context.py`.
- Updating the Memory Time Machine viewer → read `src/memdiff/audit/domain/replay.py`, `src/memdiff/adapters/replay/json_file.py`, `web/src/types/replay.ts`, and `web/src/App.tsx`.

## Public Repo Hygiene

This repository is public. Keep `.env`, `/data/`, `/runs/`, `.cache/`, `*.db`, `*.sqlite`, and personal hostnames or IPs out of git. Use `<gpu-host>` and `127.0.0.1` placeholders in tracked docs, configs, and tests.

## Verification Gates

Run all relevant checks before finishing a task:

- **Python (`src/`, `tests/`, `scripts/`)**: `uv run pytest -v && uv run ruff check src tests scripts && uv run lint-imports` (all unit tests must stay fast, deterministic, and offline). Live LLM execution belongs to the CLIs in `src/memdiff/presentation/cli/`; `scripts/*.py` stay thin wrappers that call one `main`.
- **Web UI (`web/`)**: `pnpm --dir web build` (`tsc -b && vite build` must succeed with zero errors).
